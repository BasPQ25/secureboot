Release Notes for STM32 Cryptographic middleware

Copyright © 2005-2026 STMicroelectronics

Purpose

  • STM32 cryptographic middleware consists of libraries that include a comprehensive set of cryptographic algorithms implemented in firmware and are ready to use in all STM32 Series. The main algorithms are as follows:

    • Standard cipher algorithms:

      • AES (CBC,CCM,CCM*,CFB,CTR,ECB,GCM,OFB,XTS,KeyWrap modes),
      • SM4 (CBC,CFB,CTR,ECB,OFB), Chahcha20-Poly1305, Chacha20

    • Hash methods: SHA-1, SHA-2, SHA-3, SM3, SHAKE

    • Message Authentication Codes: HMAC, AES MAC, KMAC

    • Asymmetric algorithms: ECDSA, EdDSA, SM2, ECDH, RSA PKCS#1 v1.5, RSA PKCS#1 v2.2

    • Random generator

    • Key Derivation Function: HKDF, X9.63

    • Post-quantum cryptography algorithms:

      • Module-lattice based: ML-DSA, ML-KEM,
      • Stateful hash-based: HBS-LMS, HBS-XMSS

  • The cryptographic firmware library package is based on STM32Cube architecture.

  • The library is optimized for STM32 series based on Cortex M0+, Cortex-M3, Cortex-M4, Cortex-M7, Cortex-M33, Cortex-M55 and Cortex-M85.

  • EABI: Cryptographic libraries are compatible with GCC, ARM, and EWARM compilers.

  • ACVP: Cryptographic algorithms and their components are validated by the NIST for each Cortex-M architecture, and for the fastest and smallest implementations.
    The URL of validation reports stored on NIST portal are described in “Released Libraries” table

Update History

Main Changes

  • Symmetric cryptopgraphy
    • Improved AES performance.
    • Added support for the KDF module: HKDF with SHA256/512, X9.63 KDF with SHA256 or SM3.
    • Added support of AES-GCM with IV lengths other than 12 bytes.
    • Added AES-CCM* mode.
  • Asymmetric cryptography
    • ECC compressed keys: support both for compression and decompression
    • EdDSA:
      • Support for HashEdDSA (also known as EdDSAph).
      • Improved EdDSA security against fault attacks.
      • Support for SM2 encryption/decryption (ECIES) and key exchange.
      • ECC unified API and ECDH key generation :
        • Use the same functions for ECDSA, EdDSA, and SM2.
        • Automatic algorithm selection based on the curve.
    • ECC: add the option to configure RAM usage for a dedicated function.
    • RSA: add support modular exponentiation with the private exponent for CRT or standard configuration only.
  • Support for Post-Quantum Cryptography algorithms
    • Lattice-based module: ML-DSA, ML-KEM.
    • Stateful Hash : HBS-LMS, HBS-XMSS
  • FIPS 186-5 alignments
    • RSA PKCS#1 v1.5 and v2.2 using SHAKE128/256 as hash functions.
    • SHAKE128/256 as mask generation function (MGF) for RSA PKCS#1 v2.2.
    • Deterministic ECDSA: additional optional function to call before the ECDSA signature generation function.
    • Random generation with eXtra Random Bit (XRB) to avoid random data rejection when calling key or non-deterministic signature generation such as SM2 or ECDSA.
  • Security Advisory TN1491 fixed: resolved Keccak XKCP SHA-3 reference implementation issue impact on STM32 products.
  • Added unprocessed buffer in structures cmox_gcm_common_t and cmox_ctr_handle_t.
  • Remove support for CRC.
  • Removed the “legacy_v3” folder which provided Cryptographic V3.x helpers wrappers.
  • Moved cmox_small_config.h and cmox_fast_config.h to the “templates” folder.
  • Moved cmox_low_level_template.c to the “interfaces” folder.
